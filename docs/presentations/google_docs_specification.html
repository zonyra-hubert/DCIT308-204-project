University of Ghana Campus Service Operations Optimizer (UG-CSOO)

Technical Specification: Constants, Data Structures & Algorithms

🔢 Section 1: Group Derived System Constants (15-Member Group)

Our project group consists of 15 members. Summing all 15 student ID numbers yields the index sum:

Group Index Sum = 333,907,258
Min Student ID = 10948210 | Max Student ID = 22404243

1. Parameter 1 — Road Degradation Penalty Multiplier (λ = 59.0)

  • Formula: (Group Index Sum % 100) + 1
  • Calculation: (333,907,258 % 100) + 1 = 58 + 1 = 59.0
  • Usage: Used in Dijkstra.java to weight road degradation: effectiveCost = distance_m + 59.0 * (5.0 - condition_score). Severe potholes (1.0) add a 236.0m virtual penalty.

2. Parameter 2 — Prime Hash Table Capacity (M = 761)

  • Formula: First Prime ≥ (Group Index Sum % 500) + 501
  • Calculation: (333,907,258 % 500) + 501 = 258 + 501 = 759. The first prime ≥ 759 is 761.
  • Usage: Initial capacity in CustomHashTable.java with modulo hash function hash(k) = (|hashCode| % 761) for zero-clustering O(1) lookups.

3. Parameter 3 — Operational Shift Budget Limit (W = GHS 1,089.00)

  • Formula: ((Max Student ID - Min Student ID) % 1000) + 100
  • Calculation: ((22404243 - 10948210) % 1000) + 100 = (11,456,033 % 1000) + 100 = 989 + 100 = 1089.00
  • Usage: Budget ceiling constraint in 0/1 Knapsack DP (KnapsackOptimizer.java) maximizing priority points under GHS 1,089.00.

⚙️ Section 3: Custom Algorithms Reference

🗺️ Graph & Routing Algorithms

  • Dijkstra's Shortest Path: Min-cost routing using effectiveCost = distance + 59.0 * (5.0 - condition) ($O((V+E)\log V)$).
  • Kruskal's MST: Sorts road edges and uses DisjointSet to build minimum-distance campus utility backbone ($O(E \log E)$).
  • Prim's MST: Grows utility network outward from central campus landmarks ($O((V+E)\log V)$).
  • BFS: Level-order traversal for unweighted hop distances ($O(V+E)$).
  • DFS: Recursive/stack-based traversal for cycle detection and connected components ($O(V+E)$).

💰 Optimization & Scheduling Algorithms

  • 0/1 Knapsack Dynamic Programming: $DP[i][w] = \max(DP[i-1][w], DP[i-1][w-c_i] + p_i)$ under GHS 1,089.00 ceiling ($O(N \cdot W)$).
  • Greedy Knapsack Ratio Heuristic: Sorts tickets by priority-to-cost ratio ($p_i / c_i$) to demonstrate greedy failure vs DP ($O(N \log N)$).
  • PriorityDispatchScheduler: Multi-strategy dispatcher supporting FIFO, Round-Robin, Priority Heap, and Deque Emergency Override.

🔎 Search & Sorting Algorithms

  • Binary Search: $O(\log N)$ search on sorted arrays ($\le 3$ steps for 8 items, $\le 10$ steps for 1,000 locations).
  • Linear Search: $O(N)$ sequential scan for unordered queries.
  • Merge Sort: $O(N \log N)$ stable multi-attribute sorting (Urgency desc, Budget asc).
  • QuickSort: $O(N \log N)$ in-place 2-way element partitioning sort.
  • Selection Sort: $O(N^2)$ sort minimizing physical swaps ($O(N)$ swaps).
  • Insertion Sort: $O(N^2)$ sort with $O(N)$ best-case for nearly-sorted queues.
